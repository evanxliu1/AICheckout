# Phase 12 capture tool

Captures real retail pages for the generic reader evaluation (Phase 12.2, [plan](../../../wiki/product/phase-12-reader-eval.md), [protocol](../../../docs/evals/generic-reader-protocol.md#capture-posture), `generic-reader-protocol.5`). It drives a headed Chromium on a capture-only profile with Playwright, one site per run: first a look-only **reconnaissance session** that finds the listing, item and cart and writes the draft recipe, then one capture session from the committed **recipe**. The posture rules are enforced in code; they don't depend on the operator. No reader, prototype reader or replay hook runs during capture.

```sh
node evals/merchants/capture/capture.mjs recon <domain>                # look-only session from the frame's entry host; operator drives it
node evals/merchants/capture/capture.mjs check recipes/<domain>.json   # validate a recipe; loads nothing
node evals/merchants/capture/capture.mjs run   recipes/<domain>.json   # robots check, then the recipe's steps
node evals/merchants/capture/capture.mjs serve recipes/<domain>.json   # robots check, recipe steps, then the operator's steps
node evals/merchants/capture/capture.mjs list-blocked                  # sessions (recon or capture) stopped on a bot wall, 403/429, CAPTCHA or extension check
#   options: --headless  --out <dir>  --profile <dir>  --second-session  (recon: --allowlist <popup-and-cookie-entries.json>)
npm run test:scripts            # unit tests (schema, robots, guards, platform, control server)
npm run test:capture:browser    # browser tests against the local fixture shop (127.0.0.1 only)
```

## Reconnaissance (protocol `.4`)

`recon <domain>` reads the site's `entryHost`, currency and item price band from `retail-frame-3.json` and `item-price-bands.json`, checks robots.txt, and opens the control server (as in `serve`). The operator applies the protocol's [reconnaissance rules](../../../docs/evals/generic-reader-protocol.md#reconnaissance-new-in-4) (listing, listing order, first item in the band, cart path, checkout paths) with `goto`, plain clicks, waits and `view-NN` snapshots only. The driver refuses action-state and `terms` snapshots, every purpose except `close-popup` and `decline-cookies` (`refused-recon-purpose`), and any control named like add-to-cart in the main languages (`refused-recon-add-to-cart`); same-site writes are aborted as always. The session ends with either an exclusion or `{"do":"end","findings":{listingUrl, productUrls, cartPath, checkoutPaths, termsUrl?}}`; findings may also list `stockMismatch` (found items whose add-to-cart was enabled while structured data said out of stock or backorder; recorded in the record, never in the recipe). Findings are refused unless the listing, each item and the cart path are pages the session loaded (`refused-findings-not-seen`), the listing and items are on the frame's `hosts` (`refused-findings-off-hosts`), and the session took `view-NN` snapshots of the home page and the listing (`refused-findings-no-view`). The home view may be taken on the origin or, since `.5`, on the same-site page a `goto` to the origin landed on (its redirect chain and landing are recorded in `homeLandings`). The tool then writes `recipe.draft.json` with `recon.sessionId` and `cartHost` (the host the cart path loaded on), and the record commits the ordered `navigation` list (masked URLs) for the 12.3 reviewer, who checks each recipe's listing and item against the snapshots and visit order. Reconnaissance pages are never labelled and never read for platform detection. One reconnaissance session per site (a second only after a `tool-error` one, on a later UTC day); a block or exclusion in it excludes the site, and no capture session runs.

## Recipes

A recipe is data only (`capture-recipe.3`): the site's registrable `domain` and `origin`, the `recon` session it was written from, a `listingUrl`, one or two `productUrls`, the `cartPath` and up to three `checkoutPaths` (kept **only** for robots.txt posture reporting, never a visit target: the driver refuses a `goto` or navigating click to one and stops the site on landing at one), an optional `termsUrl`, an `allowlist` of `{ purpose, target }`, and `steps`. A target is `{ role, name[, exact] }` or `{ selector }`, never coordinates, and a selector may not chain Playwright engines or enter frames (`>>`, `internal:`). Steps are `goto`, `click` (with an optional `purpose`, which must be on the allowlist), `wait` (milliseconds or a target), `snapshot` (an action state, `terms`, or an operator view `view-NN`; `checkout-1` is no longer an action state since protocol `.5`), and a final `end` with an optional judgement exclusion and `notReached` states. All URLs must be on the recipe's domain and use https (http only on 127.0.0.1 fixtures). Nothing assumes a U.S. host: any country's domain (IDN as punycode) and any language of control names work.

Purposes: `add-to-cart`, `option` (size or colour button, radio or label), `quantity-increment`, `close-popup`, `decline-cookies`. `continue-as-guest` was retired in protocol `.5`: no session enters a checkout.

A capture session refuses to start unless `recon.sessionId` names a reconnaissance session of the site that ended with findings, and the recipe's `origin`, `listingUrl`, `productUrls`, `cartPath`, `cartHost` and `checkoutPaths` equal its `recipe.draft.json` exactly (loopback fixtures without `recon` are exempt). When `cartHost` is another host, its robots.txt is read before any page and `cartPath` is checked against it. The operator takes `recipe.draft.json`, adds the allowlist and steps, and commits it. The 12.3 operator usually starts with `serve` and a recipe whose allowlist is already written, drives the session over the control server, and commits the session's `recipe.recorded.json` (the steps that ran) as the site's recipe. Neither mode adds to the allowlist at run time: a click with a purpose that is not on the recipe's allowlist is refused (`refused-not-allowlisted`). Plain clicks outside forms need no entry.

## What the tool refuses (each has a test)

| Rule | How |
| --- | --- |
| No typing, keys, `<select>`, files, coordinates or mouse | The driver has no such method; `type`, `fill`, `press`, `keyboard`, `selectOption`, `setInputFiles`, `mouse`, `clickAt` and any other name throw a `RefusalError`. A source scan test proves no tool file calls them. Targets with `x`, `y` or `position` are refused |
| Facts the page cannot fake | Every in-page check runs in a CDP isolated world, so page scripts that patch DOM prototypes do not change it. The click target is inspected where the click will land: the node at the centre of the element (`DOM.getNodeForLocation`), walked up to its control. Roles from Playwright's accessibility snapshot refuse text boxes, spin buttons, comboboxes, listboxes and options even when they have no box |
| No clicks on text fields, their labels, selects, options or file inputs | Checked before the click |
| No order, payment, sign-in or register controls | Any click (with or without a purpose) whose accessible name looks like placing an order, paying, buying now, an express-pay button, signing in or registering is refused (`refused-order-or-account`), in English, Spanish, French, German, Italian, Portuguese, Dutch, Japanese, Chinese and Korean. Deliberately conservative |
| No submit or in-form clicks unless allowlisted | A submit control is one with a form owner (a typeless `<button>` outside any form is a plain button). It is clicked for `add-to-cart`, or for `option`, `quantity-increment`, `close-popup` or `decline-cookies` only if no navigation results (any navigation during that click is aborted). Any control inside a `<form>` needs an allowlisted purpose, and its form must have no visible text, e-mail or password field, so promo-code, sign-in, newsletter and search forms are never touched. `continue-as-guest` must be outside any form. An `add-to-cart` is clicked only on a page whose path is one of the recipe's `productUrls`, and is refused if its name looks like a promo, sign-in or newsletter control or its effective form action (`formaction` wins) has a checkout, order, payment, pay, purchase, buy, login, account, register, promo, gift or search path segment (Magento's `/checkout/cart/add` is allowed) |
| No form submission by script | A top-level navigation that is a form submission (any non-GET, or a GET whose CDP navigation reason is a form submission) is aborted unless it happens during an allowlisted add-to-cart click |
| No writes by fetch or XHR | A same-site non-GET request that is not a navigation is aborted, and logged as an event, outside an allowlisted add-to-cart or quantity-increment click |
| No frames | A click point inside an `iframe`, `frame`, `object` or `embed`, or in a child frame's document, is refused; locators never enter frames |
| Same site only (`.5`) | No page of another site is ever loaded: an off-site `goto` or navigating click is refused (`refused-off-site`). Redirects are not routed by Playwright, so after every action the tool checks where the page landed: an off-site landing (a redirect, or an add-to-cart POST answered by a 303) stops the site at once as `redirected-off-domain`, with an `off-site-landing` event. A recipe checkout path is never loaded (`refused-checkout`), and a redirect onto one stops the site (`would-need-forbidden-action`, `landed-on-checkout`). Backstop for every session: a path with a segment `checkout`, `checkouts` or `secure-checkout` counts as a checkout path (unless the next segment is `cart`, so Magento's `/checkout/cart` stays allowed), and every click on a control named like checkout in the main languages is refused (`refused-checkout`; `guards.mjs` `CHECKOUT_NAME`, `isCheckoutPath`); cart wording is not matched. Popups are closed, dialogs dismissed, downloads and service workers blocked |
| Stops | Checked after every action (first, before any robots decision or refusal on the landing) and again before every `goto`, click and snapshot, so a challenge page is never snapshotted. A 401/403 or 429 main document, a visible CAPTCHA or challenge frame, a visible challenge element in the main document (`#px-captcha`, `[class*=captcha]`, Turnstile and others; the reCAPTCHA badge is ignored), bot-wall or "disable your extensions" wording, or a login route with a visible password field stops the site at once with the protocol code and a screenshot hash. Nothing is retried |
| robots.txt (`.4`) | Fetched through the browser's request context before any page of the entry host, and before the first page of every other host of the site the session loads (after the stop check when a redirect lands there). A root path `/` disallowed for `*` or `AICheckoutCapture` (RFC 9309 longest match, Allow wins ties; so `Disallow: /` plus `Allow: /` does not exclude) on any of them excludes the site (`robots-disallow-all`); nothing else does. Disallowed paths load and are recorded: the recipe's `checkedPaths`, a `robots-disallowed-path` event, and `robotsAllowed` on every captured state. Third-party hosts are never checked. User-agent lines match on the product token before any `/`, case-insensitively; non-ASCII rule paths are percent-encoded before matching. 404 and other 4xx mean no rules; 401/403 and 429 stop as blocked; 5xx or no answer stops the session as `tool-error` (RFC 9309 would assume disallow-all; `tool-error` allows the protocol's one later session) |
| Pace and scale | At least 3 s between navigations and clicks (a shorter pace is accepted only for 127.0.0.1 fixtures), at most 25 top-level navigations (`.5`: one per navigating `goto` or click, including the redirects and script navigations the page makes before the next action; more than 10 navigation requests in one action is refused as `refused-navigation-loop`, and every session records `navigationRequests`), one site at a time (a lock file), one reconnaissance session and one capture session per site (`recon-sessions.json`, `sessions.json`; a second of either kind only after a `tool-error` session of that kind, on a later UTC day, with `--second-session`) |
| Browser | Persistent profile under `profile/`; a path inside a personal Chrome or Chromium profile is refused. Playwright's default `--disable-extensions`; no extension, proxy or stealth plugin |
| Control server (`serve`) | Bound to 127.0.0.1 on a random port; 32-byte random bearer token (written 0600 to the session folder and removed at the end); refuses any request with an `Origin` or `Sec-Fetch-*` header, a Host other than `127.0.0.1:<port>`, or a non-JSON body; one command at a time; accepts only the driver's steps |

Refusals carry a `code` (`refused-submit`, `refused-in-form`, …) and an `exclusionCode` (`would-need-forbidden-action`, or `tool-error` for operational failures). An `end` step may record any of the protocol's exclusion codes (`recipe.mjs` `EXCLUSION_CODES`, the `.4` list: `geo-blocked` and `redirected-off-domain` included, `non-us-storefront` and `robots-disallow-path` retired); `end` with `tool-error` leaves the site `incomplete`, which allows the one later session. In `run` mode a refused step ends the session as `tool-error`; in `serve` mode it is returned to the operator and the session continues.

## Snapshots (`capture-snapshot.1`)

One folder per state with `page.mhtml` (CDP `Page.captureSnapshot`, the replay format), `dom.json`, `page.html`, `viewport.png`, `full.png`, `headers.json` (main document URL, status, headers), `meta.json` and `manifest.json` (SHA-256 of each file; the manifest's own SHA-256 is the state's `manifestSha256`).

- **Styles are read lazily.** `dom.json` keeps the element tree with open shadow roots inlined, text, a few attributes and boxes, and reads computed styles (display, visibility, opacity, text decoration, `checkVisibility()`) only on elements that hold their own text. The reader doesn't use a style dump: `replay.mjs` reloads `page.mhtml`, which keeps stylesheets and open shadow roots and runs no scripts, with all network blocked, so a reader reads computed styles from live layout as it will in the product.
- **Global metadata.** `meta.json` records the page's `lang`, a `locale.region` from html `lang`, `og:locale` or `geo.region` with the markers seen, and `currency` markers (ISO codes from `priceCurrency` and price meta tags, counts of currency symbols and ISO codes in the page text). These are metadata for reporting by region; no amount is read. `captureMethod` is `robot`.

## Site record (`capture-site-record.3`)

`site-record.json` is the committable, text-free result of a session: domain, recipe hash, the reconnaissance session, tool and browser version, session number and navigation count, the robots posture (URL, status, hash, the `*` and `AICheckoutCapture` rules, checked paths with `allowed`, decision `allowed` or `robots-disallow-all`) and `robotsHosts` for the other hosts loaded, the terms URL and copy hash (`prohibitsAutomated` stays `unknown` until the operator reads it), each state's URL (no query or fragment; token-like path segments replaced by `:token`), hashes and `robotsAllowed`, `notReached`, platform group and marker (read only from `empty-cart` and the first captured cart state, `cart-1` else `minicart-1`; the third-party checkout host and the checkout-host marker were dropped with `checkout-1` in `.5`), events (kind and host only), the stop (a protocol code and a reason code such as `wall-wording` or `recipe-step-refused:refused-submit`, never free text), and the outcome (`captured` if `cart-1` or `minicart-1` exists; `excluded` with a code and, for judgement codes, the evidence screenshot's SHA-256; `incomplete` after a `tool-error`). 12.3 copies these into `sites.json`.

## Blocked sites

`capture.mjs list-blocked` lists the sessions, reconnaissance or capture (`kind`), that stopped on a block (`blocked-bot-wall`, `blocked-http-403`, `blocked-http-429`, `captcha`, `blocked-extension-check`) with their reason code and evidence hash. Attended capture of these sites in a browser Evan watches was **deferred by Evan on 2026-10-05** to a later step through Claude's built-in browser; nothing for it is built here.
