# Generic cart reader harness (Phase 13)

Runs and scores the generic cart reader (`packages/cart-reader`, `readCart(document, { url })`) on the frozen page-states of one split, as [`generic-reader-protocol.11`](../../docs/evals/generic-reader-protocol.md) requires (Scoring, Pass bar, Peek policy and stop rule, Reading time). The protocol is binding and wins over this page. The reader in `packages/cart-reader` is a placeholder that always withholds (`not-implemented`); the reader developer writes the rules later, on development pages only. The three legacy store adapters (`extension/src/checkout`) are read in the same counted run and reported apart.

**Legacy adapters: n = 0.** amazon.com, bestbuy.com and newegg.com are excluded from `retail-frame-3` (`legacy-named-merchant`), and the adapters match only those hosts. So no split page is on a legacy store, and the legacy result is reported as n = 0 with that reason. The protocol's condition for replacing them (the generic reader matching them on their own stores) is therefore untested by this harness. Retiring them needs separate evidence (their own stores' pages, captured and labelled under the protocol) or Evan's decision.

```sh
node evals/reader/run.mjs --split development
node evals/reader/score.mjs --run <runId> [--failures] [--record]       # --failures: development only
# held-out A: an evaluation subagent, never the reader developer, from the main checkout only
node evals/reader/run.mjs --split heldout-a --confirm-heldout-run <n>   # n = 1 or 2; each run counts once it starts
git add evals/reader/runs.json && git commit -m "runs.json: heldout-a run <n> started"   # right away, before scoring
node evals/reader/score.mjs --run <runId> --record                      # aggregate metrics only
node evals/reader/score.mjs --run <runId> --class-only                  # the class-only analyst
npm run test:reader:browser                                             # browser tests (synthetic pages)
```

**Held-out runs** happen only from the main checkout (never a worktree or a copy, whose `runs.json` would not count the run), and the `started` row is committed straight away. `score.mjs` refuses a held-out run whose row isn't in the committed `HEAD:evals/reader/runs.json`. `runs.json` is written under an O_EXCL lock (`runs.json.lock`), and the lock re-checks the run limit. The harness runs `development` and `heldout-a` only; a fresh held-out set needs its own freeze and run limit first.

| File | What it does |
| --- | --- |
| `run.mjs` | Checks, in order, and refuses at the first failure: the split, the freeze (`freeze.mjs`'s check, with pane snapshots and variant exports re-hashed), the run limit and `--confirm-heldout-run <n>`, and, for a held-out run, committed reader, harness and legacy-adapter code (`extension/src/checkout`, `packages/rewards-core/src`). It then bundles both readers (`bundle.mjs`; inputs must be tracked by git) and runs a browser-free preflight of every frozen input. The preflight covers the pane dom and rebuild hashes, the variant label, manifest, dom and `variant.json` hashes, and the robot manifest and files; a mismatch refuses the run with no row written. Then it appends a text-free row to `runs.json`. The row goes in before any reader code runs on any page. Then, for each real page-state and each frozen variant, it loads the page once in Playwright Chromium with every request aborted:<br>• pane pages and variants are rebuilt from `dom.json` (checked against the frozen hashes) and loaded with JavaScript off;<br>• robot pages go through `replay.mjs` (MHTML, every file and the manifest checked).<br>It strips every `data-pane-*` attribute, injects the readers and reads: one untimed warm-up, three timed reads, and a stability pair 500 ms apart (each timed in the page; the wait isn't timed). The scored output is the stability pair's when both agree, otherwise withheld `unstable`. A read that throws or breaks the harness contract (`contract.mjs`) is withheld `crash`. The generic reader is removed from the page before the legacy one is injected, so neither can see the other. On a page whose URL a legacy adapter matches, the legacy reader is read the same way and recorded apart. The loaders check every hash again, and an integrity failure inside a logged run aborts it with status `failed`. Any other page failure is a harness error, and that page scores as missing. Held-out error messages name no page. Writes `runs/<runId>/outputs.jsonl` and `run.json` (machine, Chromium, reader and harness commits and dirty state, bundle inputs) |
| `score.mjs` | Refuses: an unlogged run, a held-out run not in the committed `runs.json`, a failing freeze check, or a run made on other frozen labels. It reports when the freeze file changed since the run. Outcomes are `shown-correct`, `shown-wrong`, `withheld` and `missing` (no output or a harness error; a run with any missing real page cannot pass). Precision comes with the exact one-sided 95% Clopper–Pearson upper bound of the wrong rate, Wilson 95% intervals and rule-of-three bounds, at page-state, site-cluster and operator-cluster level (operator from the frozen `retail-frame-3.json`, for scoring only). Coverage leaves out `cart-other`; a cluster's `allEligibleShownCorrect` counts it covered when every eligible page-state is shown-correct. Breakdowns: stream, state, region group, USD or not, currency (5 sites or more), observed tag. p95 read time is the nearest rank over the real pages' timed reads. Criterion 1 (upper bound ≤ 1% and p95 ≤ 50 ms on the whole split, every page-state scored) is evidence only on a held-out split, and is reported with the line that a whole-split pass says nothing about either stream alone. Also reported: the held-out run count used. Variants are reported apart, per transform, with bounds, shown-wrong by class, and the manifest's eligible, generated and skip counts. The legacy adapters are reported apart too. Neither is in criterion 1 or p95; robot pages have no variants. Errata (`evals/merchants/errata/<split>.json`, strict `reader-errata.1`) are checked against the frozen labels; only accepted ones apply, scored beside the frozen result with the count triggered by reader output |
| `dev.mjs` | Quick development loop (not a scored run; nothing goes to `runs.json`): every development page-state and variant read once after a warm-up, several pages in parallel, scored against the frozen labels; prints the counts, coverage on `cart-1`, variants per transform, read times and every shown-wrong and coverage miss. Same loaders, attribute stripping and bundle tripwire as `run.mjs`; refuses any split but development. `--only <substring>`, `--real-only`, `--concurrency <n>`, `--json <out>` |
| `detect.mjs` | Phase 13c cart page detector harness ([plan](../../wiki/product/phase-13c-cart-detection.md#measurement)): `detectCartPage` then `readCart` on every real page-state of a split, from the same bundle, loaders and attribute stripping as `run.mjs`. The badge "shows" when the detector says `cart` or `checkout` and the reader did not show a zero amount. Reports badge recall on `cart-1`, `cart-qty2`, `cart-2items` and `cart-other`, false shows on `minicart-1` and `empty-cart` (Wilson, rule of three, Clopper–Pearson upper bound, store counts), amount view against rates view on shown positives, and the detector's p95 and maximum time apart for unhinted and hinted pages (`cartUrlHint`). Default: quick loop on development (one warm-up, one timed detection, nothing logged; `--only`, `--concurrency`, `--json`); `--scored --split <split>` logs a `kind: detector` row in `runs.json` before any page is read (three timed detections, outputs in `runs/<runId>/`), and held-out A allows **one** detector run (`--confirm-heldout-run 1`), apart from the reader's two; held-out output is text-free. Misses and false shows print as `id \| state \| url \| page \| reason` on development only |
| `contract.mjs` | The reader output contract and the detector's (Zod), owned by the harness so the reader can't loosen them |
| `legacy-entry.ts` | The extension's Amazon, Best Buy and Newegg adapters behind the reader interface (`total` and `estimated-total` map to `estimatedTotal`). Typechecked by `npm run typecheck` through `tsconfig.json` (extends the extension's) |
| `bundle.mjs` | esbuild IIFE bundles. Generic: only `packages/cart-reader/src`, no `data-pane` reference (a tripwire; the attributes are stripped anyway), and no answer lookup: no domain of the split being run or of any held-out split (on development runs too), and at most 3 frame domains. Legacy: only `extension/src/checkout` and `packages/rewards-core/src` |
| `stats.mjs` | Clopper–Pearson, Wilson, rule of three, nearest-rank percentile |
| `lib.mjs` | Frozen inputs, `runs.json` (`reader-runs.1`, Zod-checked, text-free, locked) and the run limits per kind (reader rows have no `kind`; detector rows say `kind: detector`) |

**Class-only output** (`--class-only`) gives counts per class and stream (variants per transform) only: no domain, amount or page text. Classes overlap: a page can count under `coverage-miss` and `stability`, for example. Some classes can be derived from the label and the output alone: `unreadable-shown`, `tie-shown`, `currency`, `kind-wrong`, `coverage-miss`, `stability` (an unstable pair or any two of the six reads differing), `crash`, `over-budget` (any timed read over 50 ms), `harness-error` and `missing`. Classes that need the page are not: a wrong amount of the right kind and currency, or an amount shown where no total is displayed, counts as `needs-analyst`. The analyst sorts those into `region-wrong`, `distractor-accepted` (with the distractor), `amount-parse` (with the format) or `other` from the gitignored per-page outputs. **`needs-analyst` must be zero in the final class-only result.**

`runs/` is gitignored. `runs.json` is committed and holds only the text-free rows. Tests: `tests/*.test.mjs` (in `npm run test:scripts`) and `tests/browser/*.test.mjs` (`npm run test:reader:browser`). Both use synthetic pages, labels and readers only.
