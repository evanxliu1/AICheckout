# Cards

The product covers seven U.S. cash-back cards (Phase 7 is widening this; see [Catalog expansion](../system/catalog-expansion.md)). Their rules live in `CATALOG_V2` ([`packages/rewards-core/src/catalog-v2.ts`](../../packages/rewards-core/src/catalog-v2.ts)), version `2026-09-29.real.1`, verified 2026-09-29, expiring 2026-10-29, published to hosted as release sequence 1 on 2026-10-02. The catalog is generated by `npm run catalog:v2` from the gold labels in [`evals/curation/real/corpus.v2.json`](../../evals/curation/real/corpus.v2.json), never from model output. Those labels are **agent-verified, not human-verified**: an agent drafted them, and seven reviewer agents checked them against the issuer pages captured 2026-09-29. Issuer terms can change before the expiry date.

How the engine uses these rules is covered in [Reward rules](reward-rules.md). Terms are defined in the [Glossary](glossary.md).

## How it works

1. [`scripts/capture-issuer-pages.mjs`](../../scripts/capture-issuer-pages.mjs) captures the pages listed in `evals/curation/real/sources.json`; [`manifest.json`](../../evals/curation/real/manifest.json) records URL, capture date, SHA-256 and length. Captured text is gitignored (copyright).
2. [`scripts/author-real-corpus.mjs`](../../scripts/author-real-corpus.mjs) writes the gold labels (`corpus.v2.json`, version `real.v2.2`).
3. [`scripts/build-catalog-v2.mjs`](../../scripts/build-catalog-v2.mjs) maps labels to catalog rules: null cap becomes `unstated`, null activation becomes `unstated`, null `usMerchantsOnly` becomes `false`; `verifiedAt` is the latest capture date and `expiresAt` 30 days later. `npm run catalog:v2:check` fails when the generated file is stale.

## Gotchas

- **Citi rates are totals.** Citi words the portal rate as an "additional 3%" on top of 2%. The catalog stores 500 total, with 100 paid on payment. Models prompted with `baseline.1` often report increments instead (see [Evaluation](../system/evaluation.md)).
- **Citi is `points`, not `cash-back`.** Citi advertises cash back but pays it as ThankYou Points worth 1¢. Prompt `guided.2` steers some models to `cash-back` here, which is a known prompt wording bug.
- **BCE cap period.** The issuer terms say "calendar year" only in the supermarket clause, so the labels use `calendar-year` for supermarkets and `year-unspecified` for online retail and gas. The research report recommends treating all three as calendar year. The engine treats every yearly period the same, so the recommendation does not change.
- **Chase category caps are `unstated`, not `none`.** Only the 1.5% base is described as "unlimited". For an `unstated` bonus cap the engine adds `cap-unstated` and shows a range when that changes the estimate.
- **Activation `unstated` vs research "None".** The research report lists most rules as needing no activation, but the labels are null wherever the page says nothing. The engine treats `unstated` like `none` (see [Reward rules](reward-rules.md)), so this has no effect on estimates.
- **Not in the catalog:** the Chase Lyft 2% promo (through 2027-09-30), the targeted Discover-network Quicksilver 3% grocery/gas, and all statement credits (Disney streaming, Home Chef, Venue Collection) and welcome offers. Source: research report.
- An earlier v1 snapshot, `2026-09-25.pilot.2` (Quicksilver and BCE only; Best Buy and Newegg), is described in [`packages/rewards-core/README.md`](../../packages/rewards-core/README.md). `catalogSchema` still accepts v1 for cached releases.
