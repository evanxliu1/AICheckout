# Tailwind 4 for the extension, with Tailwind 3 output kept (2026-10-03)

## Context
CI runs `npm audit --audit-level=high`. GHSA-vfj7-8cjw-p6xm (published 2026-09-18) marks every `braces` version (≤ 3.0.3) high severity with no patched release. It reached the tree only through extension devDependencies: `tailwindcss` 3.4.18 (chokidar, micromatch, fast-glob) and `typescript-eslint` 8.45.0 (`@typescript-eslint/typescript-estree` → fast-glob). Production dependencies were clean. Another branch (Stage 2 M7) edits `globals.css` and adds classes, so the change had to be mechanical.

## Options considered
| Option | Chosen | Why not |
| --- | --- | --- |
| Tailwind 4 via `@tailwindcss/postcss`, theme in CSS | Yes | Smallest change to the existing PostCSS pipeline; autoprefixer still runs on every CSS file as before |
| Tailwind 4 via `@tailwindcss/vite` | | Would also drop PostCSS for `@ai-checkout/ui/styles.css` and `badge.css`; no benefit for three small pages |
| Tailwind 4 with the old JS config through `@config` | | Keeps a deprecated path; the theme is clearer as `@theme` |
| Ignore the advisory or lower the audit level | | Hides a real (dev-only) finding and weakens the gate |

## Decision
- `tailwindcss` 4.3.3 and `@tailwindcss/postcss` 4.3.3 (`optimize: false`, so Lightning CSS does not rewrite the hand-written rules); `tailwind.config.js` deleted.
- `globals.css` imports Tailwind's default theme into `@layer theme` (spacing, breakpoints, containers and other scales the v3 config did not replace), then `@theme inline` resets and redefines colors, fonts, type sizes with line heights, weights, radii and shadows on `--token-*`, so utilities emit `var(--token-*)` exactly as v3 did. No preflight. `@tailwind utilities source(none)` plus `@source '../**/*.{ts,tsx,html}'` keeps the v3 content paths, and the utilities stay unlayered at the same place in the cascade (a layered import would lose to every unlayered component rule).
- `space-y-*` is redefined with Tailwind 3's selector `> :not([hidden]) ~ :not([hidden])` (top margin, class specificity). Tailwind 4 still emits its own `:where(.space-y-* > :not(:last-child))` rules, which a five-line PostCSS step in `postcss.config.js` removes; without it the first child would gain a bottom margin.
- `typescript-eslint` 8.45.0 → 8.48.0, the first release on tinyglobby instead of fast-glob; lint output unchanged.
- The root `package.json` pins `lightningcss` 1.32.0 (the version `@tailwindcss/node` pins). npm 11.5.2 reaches it first through Vite's optional peer edge, marks its platform packages as optional peers and prunes them from `package-lock.json` (`calcDepFlags` does not clear the peer flag along optional edges), so `npm ci` on Linux would install no native binary. A root dependency clears the flag first; the lockfile then keeps all eleven binaries and is stable under `npm install`.

## Consequences
- `npm audit --audit-level=high` reports 0 vulnerabilities; `npm ls braces` is empty.
- Verified (agent-run): 33 Playwright screenshots (every popup state at 360 and 480 px, onboarding, the badge on three carts, prompts) are pixel-identical between Tailwind 3 and 4 runs; built CSS differs only in spacing written as `calc(var(--spacing) * n)` with `--spacing: .25rem`, the `@property`/`@layer properties` declarations Tailwind 4 adds, and false-positive classes from words in the source that no element uses.
- Classes added later follow Tailwind 4 semantics except `space-y-*`: `border` also sets a solid style (v3 drew none without preflight), `ring` is 1 px, `hover:` applies only on hover-capable devices, `outline-none` sets `outline-style: none`, and `space-x-*`/`divide-*` use the zero-specificity last-child form. Check new utilities against these.
- If `@tailwindcss/node` moves to another `lightningcss` version, update the root pin with it (or drop it once npm fixes the flag bug) and confirm `grep -c '"node_modules/lightningcss-' package-lock.json` is 11.
